Shuffla 카드뉴스 생성 레이어 구조

입력부터 리서치, 도메인 정책, 카피 생성, 이미지 생성, 렌더링, 저장까지의 전체 흐름

작성 기준: Shuffla SaaS dev 브랜치 / 팀원 공유용

이 문서는 “어디를 수정해야 카드뉴스 품질이 좋아지는지”를 빠르게 찾기 위한 구조 설명서입니다. 현재 생성은 단순히 GPT가 본문을 쓰고 이미지를 만드는 구조가 아니라, 입력 보강, 도메인 정책, 에디토리얼 기획, LLM 생성, 검수, 이미지 프롬프트, 렌더링이 단계적으로 연결된 파이프라인입니다.

1. 전체 생성 흐름

1. 사용자 입력/generate에서 주제, 목적, URL, 참고 이미지, 슬라이드 수 입력
2. 생성 API/api/campaigns/generate에서 인증, 브랜드, 사용량 확인
3. 컨텍스트 보강URL 수집, RSS, 외부 리서치 브리프를 keyContent에 추가
4. 메인 파이프라인generateMediaCarousel()이 전체 생성 순서 제어
5. 도메인 정책domainProfile로 리서치, 카피, 이미지 규칙 결정
6. 기획/카피 생성Editorial Director Plan과 LLM으로 슬라이드별 카피 생성
7. 검수/수리글자 수, 의미, 도메인 이탈, 금지어, CTA 누락 검사
8. 이미지/렌더링배경 이미지 생성 후 앱 렌더러가 텍스트 합성
9. DB 저장Campaign, CarouselSlide, Post, 품질 로그 저장
10. 결과 화면/campaign/[id]에서 최종 카드 확인/편집
사용자 입력
→ URL/RSS/외부 리서치 보강
→ 도메인 정책 판정
→ 카피 인텔리전스
→ 에디토리얼 기획
→ LLM 카피 생성
→ 카피 검수/수리
→ 도메인 이미지 프롬프트 생성
→ AI 배경 생성
→ 앱 렌더러로 텍스트 합성
→ DB 저장
→ 결과 화면

2. 사용자 입력 레이어

파일: app/(cms)/generate/GenerateForm.tsx

사용자가 생성 화면에서 카드뉴스 조건을 입력하는 레이어입니다.

입력값역할
topic카드뉴스 주제
contentType콘텐츠 유형
objective캠페인 목표
slideCount생성할 슬라이드 수
visualHint사용자가 원하는 비주얼 방향
productUrl참고 URL. 기본적으로 텍스트/메타데이터 수집용
productImageUrls업로드된 참고 이미지 URL. 이미지 생성 reference로 사용 가능
generationMode브랜드 기반 또는 일반 생성 모드
URL과 참고 이미지는 다릅니다. URL은 주로 텍스트 컨텍스트 수집용이고, 이미지 모델이 강하게 참고하는 것은 사용자가 업로드한 이미지입니다.

3. 생성 API 진입 레이어

파일: src/app/api/campaigns/generate/route.ts

생성 요청을 받는 서버 진입점입니다. 로그인/브랜드/사용량 확인 후, 생성에 필요한 컨텍스트를 보강하고 메인 파이프라인으로 넘깁니다.

if (body.campaignType === 'media') {
  let enrichedKeyContent = body.keyContent

  if (body.productUrl) {
    // URL 텍스트/메타데이터 수집
  }

  // RSS 보강
  // 외부 리서치 브리프 보강

  const result = await generateMediaCarousel(...)
}

이 레이어에서 핵심적으로 만들어지는 값은 enrichedKeyContent입니다. 사용자 입력 원문에 URL, RSS, 리서치 결과가 붙은 확장 컨텍스트입니다.

4. URL 수집 레이어

파일: lib/brand-url-collector.ts

외부 URL에서 페이지 제목, 설명, 본문, 이미지 alt, 메타데이터를 수집합니다.

  • 직접 HTML fetch 시도
  • 실패 시 Jina Reader fallback
  • 내부망/사설 IP 차단
  • redirect 제한
  • 응답 크기 제한

중요한 점은 이 레이어가 외부 이미지를 자동으로 이미지 생성 reference로 넘기지는 않는다는 것입니다. 외부 이미지 자동 참조는 저작권, 권한, 보안 이슈 때문에 별도 설계가 필요합니다.

5. 외부 리서치 레이어

파일: src/lib/research/carouselResearch.ts

주제에 대한 외부 사실 근거를 만들고, 슬라이드별로 어떤 근거를 쓸지 배분합니다.

필드의미
subject리서치 중심 주제
queries검색 쿼리
verifiedFacts카피에 쓸 수 있는 확인된 정보
cautions피해야 할 주장/표현
slideEvidence슬라이드별로 쓸 근거와 피할 주장
sources출처 목록

현재는 domainProfile을 사용해서 비푸드 주제에서 영양, 섭취, USDA 같은 푸드/건강 표현으로 새지 않도록 막습니다.

6. 도메인 프로파일 레이어

파일: src/lib/content/domainProfile.ts

앞으로 품질 개선의 중심이 되는 도메인별 생성 정책 파일입니다.

domain
label
searchAngles
requiredCopyAnchors
bannedCopyTerms
cautionRules
imageSubject
imageScene
imageExclusions
fallbackBodies

현재 도메인은 다음과 같습니다.

fashion, food, beauty, living, tech, health, news,
finance, commerce, education, travel, general
속성쓰이는 위치
searchAngles리서치 쿼리 생성
requiredCopyAnchors카피 프롬프트와 검수
bannedCopyTerms도메인 이탈/위험 표현 차단
cautionRules리서치와 카피 생성 주의사항
imageSubject, imageScene이미지 프롬프트
imageExclusions이미지에서 피해야 할 장면
fallbackBodiesAI 카피 검수 실패 시 대체문구
특정 브랜드명은 도메인 판정 키워드에 넣지 않습니다. 도메인은 장르/형태/콘텐츠 목적 기준으로 판정하고, 브랜드명은 URL, 사용자 입력, 브랜드 DNA, 리서치 컨텍스트에서만 다룹니다.

7. Media Carousel Pipeline

파일: src/lib/layout/mediaCarouselPipeline.ts

카드뉴스 생성의 메인 오케스트레이션입니다.

generateMediaCarousel(input)
  → layout 선택
  → brand/profile/context 구성
  → copyKnowledgeContext 생성
  → EditorialDirectorPlan 생성
  → slide plan 생성
  → LLM 카피 생성
  → 카피 보정/검수
  → Agent 보정
  → 이미지 프롬프트 생성
  → 이미지 생성
  → 렌더링
  → DB 저장

주요 함수는 generateMediaCarousel(), generateMediaSlideCopies(), enforceSemanticMeaning(), runFinalSemanticCopyGuard(), planMediaSlides()입니다.

훅 패턴, 페르소나, 감정 트리거, 서사 구조, 업종 톤 규칙을 제공합니다.

구분역할

LLM이 마음대로 카드뉴스를 쓰지 않도록 먼저 기획서를 만드는 레이어입니다.

CTA direction

여기서 슬라이드별 역할, 감정 흐름, CTA 방향, 레이아웃 힌트, 이미지 방향 힌트가 결정됩니다.

10. 슬라이드 Role 구조

Role역할
hook첫 장/초반에서 관심을 잡음
context왜 이 주제가 중요한지 배경 설명
key-point가장 중요한 핵심 기준 제시
detail구체 정보, 사용 장면, 비교 포인트, 주의점 설명
stat근거/수치가 있을 때 사용
summary앞 내용을 짧게 정리
save-cta저장/확인/비교 등 행동 유도
hook → context → key-point → detail → stat/detail → summary → save-cta

domainProfile.fallbackBodies의 hook/detail/summary/save-cta 문구는 정상 생성 때 기본으로 쓰이는 문구가 아닙니다. AI 문구가 검수 실패했을 때만 사용하는 안전 대체문구입니다.

11. 카피 생성 레이어

파일: src/lib/layout/mediaCarouselPipeline.ts

함수: generateMediaSlideCopies()

실제 LLM 카피 생성 프롬프트를 만드는 위치입니다.

프롬프트 구성:
- Editorial Director Plan
- Domain Guidance
- Story Ontology
- 브랜드 정보
- 브랜드 DNA
- 카피 인텔리전스
- 콘텐츠 기획
- 제공된 사실 및 기획 자료
- 슬라이드 구성
- 작성 규칙
- JSON 응답 형식

현재 도메인 규칙으로는 각 슬라이드 body가 requiredCopyAnchors 중 최소 1개를 반영하도록 지시하고, 도메인 금지 표현을 쓰지 못하게 합니다.

12. 카피 검수/수리 레이어

파일: src/lib/copywriting/semanticCopyCritic.ts, src/lib/layout/cardHarnessContract.ts, src/lib/copywriting/renderableCopy.ts

생성된 카피를 바로 렌더링하지 않고 검수합니다.

  • 글자 수와 줄 수
  • 본문 길이
  • 중복 본문
  • 주제 연결성
  • 문장 미완성
  • 내부 프롬프트 토큰 유출
  • 도메인 금지어
  • CTA 누락
예:
패션 결과에 "섭취", "영양", "효능" → block
금융 결과에 "매수하세요", "수익 보장" → block
뷰티 결과에 "질병 치료", "완치" → block

검수 실패 시 약한 슬라이드만 LLM으로 재작성하고, 그래도 실패하면 domainProfile.fallbackBodies로 대체합니다.

19. 앞으로의 개선 원칙

  1. 브랜드명을 도메인 분류 키워드에 하드코딩하지 않는다.
  2. 도메인 판정은 장르, 사용 장면, 콘텐츠 목적 기준으로 한다.
  3. 리서치, 카피, 이미지, 검수는 같은 도메인 정책을 공유한다.
  4. URL 수집 신뢰도가 낮으면 추측을 줄이고 참고 이미지 업로드를 유도한다.
  5. 도메인별 금지어와 필수 앵커는 실제 실패 사례를 보고 계속 보강한다.
핵심 요약: 카드뉴스 품질을 올릴 때는 먼저 domainProfile.ts를 보고 도메인 정책을 고친 뒤, 그 정책이 carouselResearch.ts, mediaCarouselPipeline.ts, semanticCopyCritic.ts, visualDirectionEngine.ts에 제대로 반영되는지 확인하는 순서가 가장 안전합니다.
